# G7-A2-S6-R2-C-R1：本地只读认证失败归因

## 决策

本门禁能确认故障发生在 Provider 认证边界，但不能在“不读取凭证、不联网、不重跑”的范围内确定具体根因。结论保持 `blocked-exact-root-cause-unproven`，不得宣传为凭证、模型或 Provider 已验证。

## 已证事实

- R2-C 同次官方定价、来源、TLS、时窗和成本合同通过后，执行器才读取环境凭证。
- 环境值不是空值；否则执行器会在 Provider 调用前关闭。
- 固定请求抵达 HTTP 层并在 162ms 返回 JSON HTTP 401，分类为 `AUTHENTICATION_REJECTED`。
- DNS、TLS、连接、超时、重定向和非 JSON 响应不是这次失败点。
- 鉴权之前已经失败，因此模型 entitlement、usage、成本和输出合同均没有被运行时验证。
- 历史 S6 与当前 R2-C 在同一 source-locked 传输合同下都只发送第一条 canary、得到 HTTP 401、零重试且不发送第二条。
- 所有者证据曾声明凭证已轮换、安全注入已更新且格式已检查；该证据是所有者陈述，不是目标进程中的凭证身份或有效性证明。

## 根因假设排序

1. 目标运行进程继承了旧值或来自非预期注入源。轮换与更新声明之后仍出现相同 401，使其成为最优先假设；由于没有身份指纹且本门禁禁止读取凭证，仍未证明。
2. 注入值本身已失效、被撤销、属于错误账户/项目/Provider 或作用域不匹配。所有者声明构成反向证据，但不能替代运行时认证。
3. 外部认证合同或账户策略发生变化。当前 client 与已评审本地合同一致，但同次官方定价页只证明 Anthropic API/base URL 存在，不证明认证 header 的当前外部语义。

## 下一最小证据

建议先由所有者在仓库外重新绑定预期 DeepSeek 凭证并重启承载 Codex/终端的目标进程。之后另行授权 `G7-A2-S6-R2-C-R1-A`：只在与后续 executor 相同的启动环境读取一次凭证，输出 `present`、`single-line`、`no-boundary-whitespace`、`no-surrounding-quotes` 四个布尔值；禁止输出值、长度、前后缀、哈希或指纹，网络和 Provider 调用保持 0。

即使该探针全部通过，也只证明注入形态，不证明凭证身份或有效性。新的 Provider canary 必须再单独授权，并重新刷新价格。
